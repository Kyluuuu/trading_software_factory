# Task 001: Foundation

Status: implemented; validation evidence is recorded in the completion report.

Scope is repository/tooling, immutable safety values, typed fail-closed configuration, explicit position states, risk-approved order capability, disabled live adapter, architecture enforcement, tests, security checks, and CI. No strategy, indicators, training, downloads, broker authentication/submission, or trading behavior is included.

An independent review of this milestone produced remediation recorded in ADR 0002: runtime order validation at execution and adapter boundaries, a token-guarded single approval authority, an import-resolving architecture scanner, removal of the unsafe `PENDING_EXIT`/`CANCEL` transition, exact-integer contract quantities, one configuration pipeline so environment variables always win, globally enabled subprocess rules with line-level exceptions, `detect-secrets` wired into the shared command, SHA-pinned hook repositories, and session tests. Each fix landed with a failing regression test first.

A regression fix must begin with a failing focused test. CI maps directly to `scripts/verify.py`; generated settings schema and `uv.lock` are checked for drift. Repository setup installs the pre-commit hook, with `make hooks` available to repair an existing checkout.

Follow-on offline research addition (2026-11-25): a six-symbol stock/ETF allowlist (AAPL, MSFT, NVDA, SPY, QQQ, VOO), stop-based per-proposal risk assessment against 1% equity, 3% daily loss and 10% peak-equity drawdown budgets, weekdays/session hours, and round-trip estimated per-share costs. An explicit account snapshot is required for every assessment; there is no persistence, holiday calendar, aggregate open-order exposure, fill monitoring, or guaranteed stop execution. Separate read-only Alpaca paper REST discovery fetches tradable assets and account equity using ignored local credentials; previous-close equity is not the session-opening snapshot for risk decisions. No strategy, automated trading, or broker submission was added; the disabled adapter remains unchanged.

These ceilings cannot be relaxed through settings. Added pure mean-reversion and breakout candle signals and an independent one-bar replay for each strategy with next-bar signal timing, adverse stop/close proxy, commission/slippage, metrics and a retrospective positive-profit ranking. Ranking allocations are research-only recommendations, not shared capital allocation. No downloading, tick/order-book data, realistic HFT fills, aggregate concurrent exposure, persistent halt state, calendar, walk-forward validation, rolling retraining, ML or broker routing is implemented. No profitability claim is made; live submission remains disabled.

Read-only historical data follow-on (2026-11-25): `uv run python -m mnq_system.backtest.cli --alpaca --symbol AAPL --start 2026-01-05T15:00:00Z --end 2026-01-05T16:00:00Z` requests paginated 1-minute stock bars from Alpaca's historical market-data endpoint with IEX feed and raw adjustment, using local paper credentials. Extended offline research (2026-11-25): `uv run python -m mnq_system.backtest.cli --alpaca --year --symbol AAPL --walk-forward` fetches the previous 365 days (ending 20 minutes before invocation), compares seven fixed-parameter causal strategies (mean reversion, breakout, trend following, momentum, volume spike, rolling VWAP reversion, volatility expansion), and reports rolling prior-window selections and subsequent independently replayed outcomes. The prior-ranking comparison itself is fixed-parameter. A subsequent offline supervised outcome model refits at each train/test boundary from completed training trades, grouped by strategy and preceding price direction; it gates simulated test entries using frozen per-window estimates, with unseen or insufficiently sampled patterns disabled. This is actual retraining of a simple empirical classifier, not parameter optimization, persistent learning, autonomous continuous operation, a single netted portfolio, or realistic high-frequency fill modeling. A year of IEX minute data can require many paginated calls and depend on account entitlements; cash is selected when no training candidate qualifies. No order submission is enabled.

Phase 2 point-in-time features (2026-11-25): `uv run python -m mnq_system.features.build` reads verified local raw Alpaca partitions and writes versioned monthly Parquet feature matrices under ignored `data/features/iex/raw/1min`; `uv run python -m mnq_system.features.report` checks their counts, timestamps and integrity. Forty-four catalogued features include market, volatility, mean reversion, momentum, trend, session VWAP, volume, breakout, confirmed swing structure and exchange-time measures. Rows are timestamped with source minute and `available_at=timestamp+1 minute`; all formulas use current/prior completed bars only, so they cannot be used at their source minute open. XNYS regular-session bars only; unobserved minute gaps reset rolling history, session VWAP resets by session, and no missing values are imputed. Nulls represent warm-up or undefined ratios and remain null in Parquet. Month-boundary warm-ups reset rather than use future or undocumented carryover. No labels or ML were added.

Phase 2.5 feature validity (2026-11-25): feature partitions now carry a hash of the catalog and generator source, a hash of the generation policy, and a generator version alongside source checksum and feature version. Mismatched lineage invalidates reads and triggers a rebuild. `features.asof.join_as_of` and `FeatureStore.at_decision` reject requests before the declared minute-close `available_at`, naive timestamps, and unordered rows. Direct raw partition reads remain available for integrity audits; future decision consumers must use the guarded API, not direct `read`. `uv run python -m mnq_system.features.training_readiness` reconciles raw and feature regular-session timestamps against XNYS, computes row and per-feature non-null coverage, gap/null/warmup percentages and estimated missing-minute recovery rows. A typed 99.0% minimum symbol-coverage gate and a conservative per-feature exclusion list report research eligibility; actual market-data receipt time is not measured, and the report does not authorize live use, labels or models.

Phase 3 offline supervision (2026-11-26): `uv run python -m mnq_system.labels.build` generates month-partitioned, checksummed Parquet labels from verified local features and raw bars; `uv run python -m mnq_system.labels.report` summarizes mature outcomes and illustrative chronological purged/embargoed splits. Prediction time is the feature's guarded `available_at`, entry is the next one-minute candle open, and forward outcomes at 5/15/30/60 minutes mature one minute after their exit candle timestamp. Three target and three stop widths (0.25/0.50/1.00%) combine with four time barriers for 36 first-hit variants per observation. If both barriers occur within a candle, the stop wins conservatively; later open gaps are priced at their open. Only full contiguous same-session 60-minute horizons are emitted; labels are never filled across missing candles or a session close. Raw, feature, and next-partition source checksums plus generator/configuration hashes invalidate stale partitions. Risk-adjusted outcome values are null when prediction-time ATR or volatility is unavailable. These are hypothetical research labels without execution costs, not executable trades or ML training. No broker submission is enabled.

Phase 4 offline baseline model research (2026-11-26): `uv run python -m mnq_system.models.baselines` uses only verified local partitions for SPY, QQQ, AAPL, MSFT, NVDA and TSLA, the existing as-of feature join and purged/embargoed splits. Fixed-parameter logistic regression, random forest, XGBoost and LightGBM predict only 15- and 30-minute down/neutral/up directions using per-symbol admissible features. A seeded random predictor, constant long/short and training-majority baselines are compared on an untouched test split. Per-symbol hypothetical non-overlapping gross trade returns omit transaction costs; cross-symbol results are classification-only, not capital allocation. JSON output under ignored `data/research/` includes confusion matrices, classification and trading metrics, and feature rankings. Models are not serialized, deployed or connected to broker submission.

Offline signal-discovery follow-on (2026-11-26): `uv run python -m mnq_system.models.signal_discovery` reuses verified Phase 4 partitions, as-of joins, purged splits and fixed-parameter baseline estimators for descriptive held-out mutual information, Pearson information coefficient against signed forward return, rank IC, and pooled group-only/leave-one-group-out ablations. The full catalog is classified into time, price, volatility, mean reversion, trend, volume, breakout and market structure; groups without admissible pooled features are explicitly untestable rather than scored zero. Analysis uses the previously inspected test interval and is exploratory, not fresh out-of-sample validation. Results remain ignored local research JSON; no new model classes, datasets, live actions or broker submission.

Phase 1 historical ingestion (2026-11-25): `uv run python -m mnq_system.data.ingest --symbols SPY QQQ AAPL MSFT NVDA AMD META TSLA --days 365` downloads read-only Alpaca IEX raw 1-minute bars for the preceding 365 completed UTC days into ignored `data/alpaca/iex/raw/1min/symbol=.../year=.../month=.../bars.parquet` files. Each symbol-month has an interval and SHA-256 manifest; completed partitions are skipped on retry and corrupt/interrupted partitions replaced. Bounded HTTP retries cover 429/5xx/network errors. `uv run python -m mnq_system.data.coverage_report` reads locally stored bars and reports expected XNYS regular-session minutes including early closes, observed/missing bars, missing dates and invalid partitions. Empty months and missing IEX bars are reported, not silently imputed. Neither the full-year download nor a complete dataset is claimed by tests; run the command and inspect coverage before research use. Broker submission remains disabled.
